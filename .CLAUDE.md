# Modélisation conceptuelle d'un form engine
Le domaine
Un formulaire est un ensemble de champs qui collectent des données, les valident, et les soumettent.

## Les concepts fondamentaux
#### 1. Field (le sujet)

A une identité (nom)
A une valeur courante
A un état (idle, touched, validating, valid, error, disabled, submitting)
Émet des événements de cycle de vie : mount, change, blur, submit, unmount
#### 2. Validator (la règle)

Reçoit une valeur → retourne un verdict (valid | error + messages)
Peut être sync ou async
Est composable (N validators sur un field)
Ne connaît pas le field, ne connaît pas le form — il reçoit une valeur, c'est tout
#### 3. Behavior (la réaction)

Observe les événements du field
Produit des effets : modifier l'UI (flags), fetch des données, verrouiller, préfill…
Est un plugin : empilable, indépendant des autres behaviors
A accès au contexte du field (lire/écrire la valeur, connaître l'état)
#### 4. Controller (le chef d'orchestre)

Possède un field, ses validators, ses behaviors
Dispatche les événements de vie vers les behaviors
Agrège les résultats (flags, erreurs) en un snapshot unique
N'a pas d'opinion sur comment afficher ou stocker — il expose un état observable
#### 5. Form (le conteneur)

Agrège N controllers
Connaît l'état global (tous les fields valides ? au moins une erreur ?)
Orchestre la soumission (bloquer si erreur, déclencher submit sur chaque field)

## Les relations 
Form 1──* FieldController
FieldController 1──1 Validator (ou 1──* si composite)
FieldController 1──* Behavior
Behavior ──> lit/écrit via Context
Validator ──> reçoit valeur, retourne verdict

## Le flux (événement → rendu)
Événement (change, blur, submit)
    │
    ▼
Controller dispatche aux Behaviors
    │
    ▼
Behaviors retournent des flags / effets
    │
    ▼
Controller déclenche le Validator
    │
    ▼
Validator retourne un verdict
    │
    ▼
Controller agrège tout → nouveau Snapshot
    │
    ▼
L'adapter (React, Vue, etc.) observe le snapshot → re-render

# Ce qui est important
Le Form et les Controllers ne savent pas qu'ils sont dans React, dans Redux, ou dans un terminal. Ils exposent un état observable.
Les Validators ne savent pas qu'ils sont dans un form. Ils reçoivent une valeur.
Les Behaviors ne savent pas comment s'affiche le field. Ils retournent des intentions (flags), pas du JSX.
L'adapter est un traducteur jetable : il traduit le snapshot en props pour le framework cible.
C'est cette séparation qui rend le système testable, portable, et extensible sans effet domino.


# Objectif final obtenir ce type de rendu :

```ts
// carFormConfig.ts
const cardType = {
  name: "cardType",
  label: "Card type",
  validator: [new RequiredValidator(), RemoteEmailValidator(),],  
  behaviors: [fetchOptionsOnMount(fetchCardsApi), lockWhileValidating()],
};

const email = {
  name: "email",
  label: "Email",
  validator: new EmailValidator(),
  behaviors: [lockWhileValidating()],
};

export const fields = [cardType, email, /* ...8 autres */];
```

```tsx
// Render
<Form id="car">
    {fields.map((f) => <TextField key={f.name} {...f} />)}
</Form>
```

```tsx
// SubmitButton.tsx
export function SubmitButton(props: SubmitButtonProps) {
    const formId = props.formId;
    const dispatch = useAppDispatch();
    const form = useAppSelector((state) => state.form[formId]);

    if (!form) {
        return null
    }

    return <Button
        variant="contained"
        color="primary"
        type="submit"
        onClick={() => dispatch(createCarThunk())}
        disabled={hasFieldError(form) || form.status === "submitting"}
        loading={form.status === "submitting"}
    >
        Submit
    </Button>
}
```


```tsx
// Branché au formulaire "MyFormId"
<SubmitButton formId={"MyFormId"} />
```

### Règle simple pour savoir quand utiliser un Validator ou un Behavior
- Est ce que cette valeur est acceptable ? (email, adress, model de voiture ..etc). Sinon c'est un behavior.

`RemoteEmailValidator` → Validator. Même si c'est async, ça répond "oui/non cette valeur est correcte".
`fetchOptionsOnMount` → Behavior. Ça ne valide rien, ça charge des données.
`lockWhileValidating` → Behavior. Ça pilote l'UI, pas le verdict.

|          | Validator | Behavior |
|:---------|:---------|:---------
|Sémantique|Prédicat sur la valeur|Effet/réaction à un événement|
Sortie| valid / error + messages | UI flags
Impact sur submit |	Bloque | Ne bloque pas
